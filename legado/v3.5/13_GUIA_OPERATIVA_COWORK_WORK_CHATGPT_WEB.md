# Guía para Claude Cowork, ChatGPT Work y ChatGPT Web — v3.5
**Primero lee:** `16_GUIA_SEMANA_EN_15_MINUTOS.md`, que contiene el recorrido semanal y prompts de inicio. Esta guía define el reparto entre herramientas.

## Fuente única de verdad
El directorio local descomprimido `Alexander-Contenido` guarda archivos y estado. No usar recuerdos de chats como aprobación. Al cambiar de plataforma, **copia los documentos aprobados**, nunca reconstruyas un guion desde memoria.

## Ruta 1 — Claude Cowork
- Utiliza un proyecto editorial si tu cuenta ofrece acceso a carpetas, con `COWORK_INSTRUCCIONES.md`.
- Confirma que efectivamente puede **leer y editar** una copia de prueba del directorio; la disponibilidad de funciones depende del plan y versión.
- P00 primera vez; P01 al comienzo de cada semana; P02/P03 para guiones; P04 para tomas; P10 para resultados.
- Antes de pasar a Code, revisa `SCRIPT.md`, `PRUEBAS_Y_CLAIMS.md`, `INGESTA.md` y las aprobaciones G2/G3/G4. Cowork y Code NO deben suponerse sincronizados por arte de magia.

## Ruta 2 — ChatGPT Work
- Crea el espacio de dirección editorial y pon el paquete (o documentos base) a disposición de la tarea. Si el modo dispone de acceso autorizado a archivos, verifica permisos reales.
- Usa los mismos prompts, plantillas y gates. No es necesario instalar Claude para redactar guiones en Work.
- Devuelve cualquier borrador al directorio canónico; no mantener dos históricos.

## Ruta 3 — ChatGPT Web con Proyecto
- Adjunta documentos base y utiliza `09_PROMPTS_MAESTROS.md`.
- La conversación web no puede por defecto guardar archivos directamente en tu Windows. Descarga y sustituye los ficheros cambiados de forma manual o mediante un flujo autorizado.
- Para vídeo de la semana adjunta **solo su expediente**, no el ZIP completo repetidamente.

## Segundo workspace — HyperFrames con Claude Code/Codex
- Los agentes de código reciben `CLAUDE.md`, `07_ESPECIFICACION_HYPERFRAMES.md`, `18_INGESTA_COLOR_EXPORT_Y_QC.md`, el `EDIT_PLAN.md` aprobado y la carpeta **de un solo episodio**.
- P05 prepara únicamente el plan; G5 autoriza. P06 prueba escena difícil; P07 crea rough cut; P08 corrige; P15 prepara escenas para el editor.
- CapCut Gratis/Shotcut ensamblan piezas cuando sea necesario, sin gastar tokens del agente. G7 picture lock; G7.5 QC del master; G8 publicación humana.
- No reinstalar HyperFrames en cada semana; fijar versión/skills y registrar cambios.

## Registros que deben actualizarse
1. `registro/DECISIONES.md`: quién, qué, evidencia, versión y aprobación.
2. `registro/ESTADO.md`: bloqueos y siguiente gate.
3. `semanas/AAAA-WNN/PLAN.md`: lote y horas aprobados.
4. `videos/Vxx/BRIEF.md`, `SCRIPT.md`, `PRUEBAS_Y_CLAIMS.md`, `EDIT_PLAN.md`: expediente del vídeo.
5. `REGISTROS` de entregas y métricas: solo datos observados y URLs reales.

## Seguridad operativa
- Ninguna herramienta publica o realiza compras por su cuenta.
- Aliases de Alexander, paleta y primera miniapp siguen pendientes hasta aprobación real.
- Los MP4 archivados offline **no impiden planificar**; para reutilizar/editar el original, hay que restaurarlo siguiendo `14_POLITICA_ARCHIVO_Y_RESTAURACION.md`.
- Referencias visuales externas son solo técnicas, no activos de publicación.
